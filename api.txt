================================================================================
DISTRIBUTED ONLINE CHESS PLATFORM - API DOCUMENTATION
================================================================================

BASE CONFIGURATION
--------------------------------------------------------------------------------
Base HTTP URL:      http://localhost:8080
Base WebSocket URL: ws://localhost:8080/ws
Authentication:     All endpoints (except Auth) require an HTTP Header:
                    Authorization: Bearer <your_jwt_token>


================================================================================
1. REST API ENDPOINTS
================================================================================

1.1 REGISTER NEW USER
---------------------
Method:        POST
Endpoint:      /api/auth/register
Auth Required: No
Payload:       JSON
               {
                 "username": "player1",
                 "email": "player1@example.com",
                 "password": "securepassword"
               }
Returns:       200 OK on success.
               400 Bad Request if username is taken.
               500 Internal Server Error on failure.

1.2 USER LOGIN
---------------------
Method:        POST
Endpoint:      /api/auth/login
Auth Required: No
Payload:       JSON
               {
                 "username": "player1",
                 "password": "securepassword"
               }
Returns:       200 OK. Body contains the JWT string as plain text.
               401 Unauthorized on bad credentials.

1.3 GET LIVE GAME STATUS
---------------------
Method:        GET
Endpoint:      /api/game/{gameId}/status
Auth Required: Yes
Description:   Retrieves the current, volatile state of an active game from Redis.
Returns:       200 OK. Body contains JSON:
               {
                 "fen": "rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1",
                 "whitePlayer": "player1",
                 "blackPlayer": "player2",
                 "whiteTime": "PT3M", 
                 "blackTime": "PT3M",
                 "moves": ["e4", "e5", "Nf3"]
               }

1.4 GET GAME HISTORY
---------------------
Method:        GET
Endpoint:      /api/game/{gameId}/history
Auth Required: Yes
Description:   Retrieves a game's persistent record from PostgreSQL.
Returns:       200 OK. Body contains JSON:
               {
                 "id": 1,
                 "whitePlayerName": "player1",
                 "blackPlayerName": "player2",
                 "status": "ONGOING", 
                 "moves": ["e4", "e5", "Nf3"],
                 "started": "...",
                 "ended": "..."
               }

1.5 GET User STATS
---------------------
Method:        GET
Endpoint:      /api/users/me/stats
Auth Required: Yes
Description:   Retrieves statistics of the user.
Returns:       200 OK. Body contains JSON:
               {
                "winAsWhite" : int,
                "winAsBlack" : int,
                "loseAsWhite" : int,
                "loseAsBlack" : int,
                "drawAsWhite" : int,
                "drawAsBlack" : int,
               }

1.6 GET User Games
---------------------
Method:        GET
Endpoint:      /api/users/me/games
Auth Required: Yes
Description:   Retrieves Last 10 games of user.
Returns:       200 OK. Body contains Array of JSON:
               [
                {
                 "id": 1,
                 "whitePlayer": "player1",
                 "blackPlayer": "player2",
                 "status": "ONGOING", 
                 "moves": ["e4", "e5", "Nf3"],
                 "started": "...",
                 "finished": "..."
                }
               ]


================================================================================
2. WEBSOCKET (STOMP) DESTINATIONS
================================================================================
Connection: Connect to /ws and pass the JWT in the connection headers.

2.1 CLIENT SENDS (Triggers Server Actions)
------------------------------------------

Action:      Join Matchmaking
Destination: /app/match-making/join
Payload:     None (Server identifies user via JWT Principal).

Action:      Cancel Matchmaking
Destination: /app/match-making/cancel
Payload:     None.

Action:      Submit a Move
Destination: /app/game/{gameId}/move
Payload:     String containing the move in Standard Algebraic Notation 
             (e.g., "e2e4").

Action:      Game Actions (Resign/Draw)
Destination: /app/game/{gameId}/action
Payload:     String: "RESIGN" or "DRAW".


2.2 CLIENT SUBSCRIBES (Listens for Server Events)
-------------------------------------------------

Event:       Match Found Notification
Topic:       /user/queue/match-making
Receives:    JSON containing match details.
             {
               "gameId": 123,
               "opponentId": "player2",
               "playerSide": "WHITE" // or "BLACK"
             }

Event:       Opponent's Move Broadcast
Topic:       /topic/game/{gameId}/move
Receives:    JSON Move object from chesslib containing move details 
             (from, to, piece, promotion, etc.).

Event:       Game Over / Status Event
Topic:       /topic/game/{gameId}/event
Receives:    String containing the GameStatus enum value 
             (e.g., "WON_WHITE_CHECKMATE", "DRAW_AGREEMENT").

Event:       Draw Offer Received
Topic:       /user/queue/game/{gameId}/draw-offer
Receives:    String containing exactly: "Draw offer received".
